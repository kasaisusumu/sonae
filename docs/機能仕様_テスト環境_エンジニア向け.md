## 1. テスト環境とは

動かしている。ここで何をしても、ほかの環境（利用者が使うもの）のデータや画面には影響しない。

- URL: `https://sonae-test.vercel.app`
- 追跡するコードの置き場所（git ブランチ）: `test`
- 機能: 基本的には `test` ブランチに入っているコードがそのまま動く（ブランチの中身が
  この環境の仕様そのもの。§3 参照）

## 3. この環境で動く機能（`test` ブランチの内容）

アプリの基本機能（Google カレンダーの予定取り込み、準備リストの自動生成、編集の学習、
Web Push 通知、説明欄への書き込み など）はそのまま動きます。詳しくは
`機能仕様_エンジニア向け.md` を参照してください。

このテスト環境で特に確認してほしい機能は次の 2 つです。

### 3.1 「未来の自分へ」（メッセージ機能）

いつ入るか分からない予定のために、先に思い出したいことを書いておく機能です。

- **書く**: `/failures`（ナビ名「未来の自分へ」）の「メッセージを書く」で、本文・キーワードを
  指定する。予定に紐づけなくても作れる。**ジャンル・カテゴリ・一致条件（scope）の指定 UI は
  無い**（2026-10〜。メッセージはキーワードが決まっていること自体が条件なので、項目のような
  3択は持たない）。
- **一致**: 予定が取り込まれた・更新されたとき、キーワードが当てはまれば、その予定に
  「💌 未来の自分へ」として結びつき、プッシュ通知が届く。キーワードが決まっていなければ
  自動では一致しない（あとでキーワードを足せば効くようになる）。
  ジャンル・カテゴリ・`scope:"similar"/"once"` による一致は、2026-10 以前に作られた既存データの
  後方互換としてバックエンドに残っているだけで、新規作成・編集では常に `scope:"keyword"` になる。
- **予定詳細での扱い**: 結びついたメッセージは予定詳細の「💌 未来の自分へ」枠に出る。
  確定後・スキップ後のものも出て、どの状態でも内容（本文・キーワード）をいつでも直せる。
  ✕ で「この予定からだけ外す」こともできる（メッセージ本体は残り、同じキーワードでは再度結びつかない）。
- **学習されたマニュアル（`/savings`）での扱い**: 学習対象の予定の下に同じ「💌 未来の自分へ」枠が出て、
  同じ編集欄で直せる（§6.8 の注意と同じく、学習対象でない予定は出ない）。
- **予定が終わったあと**: 終わった予定に結びついていて、まだ確認していないメッセージは
  「確定カード」として `/failures` の上部と予定詳細に出る。AI が次回への引き継ぎ内容・キーワードを
  あらかじめ埋めてくれるので、直すところだけ直して「この内容で確定」を
  押す（そのままでよければ何も直さずに確定できる）。「今回は更新しない」も選べる。
- **通知**: 一致したときに「未来の自分へのメッセージ」、予定が終わったあとに「○○のメッセージを
  更新しませんか？」が 1 予定につき 1 回届く（いずれもテスト環境では §5 の制約あり）。

### 3.1b 準備リストの項目ごとの「次回の出し方」（範囲つきルール）
- 項目を足したり消したりすると、次回どの予定で出すかを選べる。**選択肢は「今回だけ」
  「似た予定のとき」「この名前の予定だけ」の3つ**（2026-10-10〜。一時期は2択のみだった）。
  項目名の下に常に3つのボタンが一列で出ており、タップするだけで即切り替わる（開く必要はない）。
  横一列に収めるため、ボタンの表示文言は「今回だけ」「似た予定」「この名前」と短い
  （意味は同じ）。「この名前」は、タップした時点の予定名から自動でキーワードを1つ決める
  （`pickKeyword`、`lib/text-norm.ts`）。
- ∨ で詳細を開くと、「『＿＿』のとき」という文章の空欄でキーワードを別の語に直せる
  （自動で決まった語と違うものにしたいとき用の任意オプション）。空にすると「今回だけ」に戻る。
- ボタンの右に `InfoHint id="scope-quick-toggle"` が付いており、押すと3択の説明を読める。
  予定詳細を開いたとき `User.scopeHintDismissedAt` が `null` なら、同じ説明を
  全画面ポップアップで自動表示する（`scope-hint.tsx`）。「今後表示しない」＋OK で
  `dismissScopeHint()` を呼び、以後表示しなくなる（`desc-link-hint.tsx` と同じ仕組み）。
- 「未来の自分へ」のメッセージは、この3択を持たない（2026-10〜。キーワードが決まっていること
  自体が条件のため）。本文＋キーワード文章欄（`KeywordSentenceField`）だけで、常に
  `scope:"keyword"` で保存される。
- 追加・削除の直後に AI（OpenAI）が「今回だけ」「似た予定のとき」のどちらかを推奨する
  （「この名前の予定だけ」は手動選択のみ。AI は提案しない）。推奨は「提案」の印で、
  放置すればそのまま使われる。1 予定につき AI に聞くのは最大 8 回。
  OpenAI 未設定の環境では「今回だけ」になる。
- 範囲ルールは、従来の自動学習より優先する。「今回だけ」は自動学習の対象にもならない。
- 学習内容の画面の上に「次回の出し方のルール」の一覧があり、ルールを外せる（確認あり）。
- 同じ項目に複数のルールが当たったときの優先順位: キーワード ＞ 似た予定。
- 追加のマイグレーションは `20261004100000_checklist_scope`（テーブル 2 つの追加のみ）、
  `20261008000000_google_sync_error`（Google 連携切れの可視化。無関係の変更）、
  `20261010120000_scope_hint`（`User.scopeHintDismissedAt` の追加のみ）。
  いずれもテスト用 Neon ブランチに適用済み。

### 3.2 失敗ログ機能は無い

以前あった「失敗ログ」機能（うっかりミスの記録、先回りの警告、防げた件数・推定節約額の表示、
「防ぎたい失敗」の初回ポップアップ）は、このテスト環境では**動作しません（コードを削除済み）**。
関係する DB テーブル（`FailureLog`、`SavingsEntry`、`FailureDismissal`）と `Event` の一部の列は、
データを残すために削除せず残してあるが、アプリからは一切参照していない。

## 4. 環境変数

| 変数 | この環境での値・扱い |
| --- | --- |
| `DATABASE_URL` / `DIRECT_URL` | テスト用 Neon ブランチの接続文字列（`DIRECT_URL` はマイグレーション用） |
| `APP_BASE_URL` | `https://sonae-test.vercel.app` |
| `GOOGLE_REDIRECT_URI` | `https://sonae-test.vercel.app/api/auth/google/callback` |
| `NOINDEX` | `true`（§5 の検索除外を有効化） |
| `SESSION_SECRET`、`CRON_SECRET`、`ADMIN_EMAIL`、`VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT`、`OPENAI_API_KEY`、`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` など | 別の環境と**同じ値**を設定している（Google の OAuth クライアント、OpenAI の API キーなどを共用） |

共用の API キーを使っているため、Google Calendar API・OpenAI API の利用枠（quota）や料金は
他の環境と合算される。テスト中に大量の AI 呼び出しや同期を行うと、その分の利用量が増える。

## 5. 検索エンジンに出さない仕組み（NOINDEX）

- `app/robots.ts`: `/robots.txt` は全環境で `Allow: /`（クロールは許可）。分析サイトなどが
  テスト環境の公開ページを読めるようにするため。
- `app/layout.tsx`: `NOINDEX=true` のとき `<meta name="robots" content="noindex, nofollow">` を出す。
  検索に出さないための対策は、この meta タグだけで行う（検索エンジンは noindex を守ってインデックスしない）。

`NOINDEX` を設定していない環境では、meta タグも出さないため、通常どおり検索エンジンに出る設定になる。
（以前は robots.txt でも全面拒否していた。分析サイトが読めなくなるため、2026-10 に拒否をやめた。）

## 6. 既知の制約・注意点

- **自動通知が届かない定期ポーリングの対象外**: 新規予定の検知は、アプリを開いたとき・
  「カレンダーから取り込む」ボタンを押したときに行われる。定期実行（GitHub Actions の
  `poll-calendar`）はテスト環境の URL を叩いていないため、テスト環境では新着予定の
  プッシュ通知は自動では届かない。
- **Google Calendar の即時 webhook は未設定**: Google 側でのドメイン確認が必要なため、
  テスト環境では変更の即時取り込みは行わない（定期取り込みと手動取り込みのみ）。
- **マイグレーションは自動で当たらない**: `prisma/migrations` に新しいマイグレーションを
  追加したら、`prisma migrate deploy` をテスト用 Neon ブランチに手動で実行する必要がある
  （`テスト環境構築手順.md` の「マイグレーションの当て方」）。適用前にコードを動かすと、
  新しいテーブルが無いためページがエラーになる。
- **Git への push による自動デプロイが、テスト環境の URL に反映されない場合がある**:
  `sonae-test` の Vercel 側の「Production Branch」が `main` のままになっていると、
  `test` に push しても `sonae-test.vercel.app` には反映されず、Preview 扱いになる。
  2026-10 に Production Branch を `test` に直したので、通常は push だけで反映される。
  もし元に戻っていたら、`test` を checkout したうえで `npx vercel --prod --yes` で手動デプロイする
  （詳細は `テスト環境構築手順.md`「構築時に踏んだ不具合」）。
- **実アカウントの Google 連携は、ブランチ作成時点のコピーのまま**: テスト用 Neon ブランチは
  本番からの分岐（§7）なので、分岐前から Google 連携していた実ユーザーのデータも入っている。
  これらのリフレッシュトークンは、分岐後しばらくすると（OAuth アプリがテスト公開状態のため
  概ね1週間ほどで）失効し、`invalid_grant` でカレンダー取り込みが失敗するようになる
  （2026-10 にこれが原因で「予定が取り込まれない」不具合として気づいた。
  `UserGoogleAccount.syncError` が立っていれば、これが原因だと分かる。直すにはその本人が
  `/settings` の「再接続」で
  Google に入り直すしかない）。開発確認には、この影響を受けない §7 の固定テストアカウント
  （Google 未連携）を使う。

## 7. 運用メモ

- **コードを更新する**: `test` ブランチに push する（または上記のとおり手動デプロイする）。
  `main` にはマージしない限り、この環境の内容は変わらない。
- **DB の状態**: テスト用 Neon ブランチは、作成時点の状態からのコピーに、この環境で行った
  書き込みが加わったもの。他の環境のデータには影響しない。
- **環境ごと削除したくなったら**: Vercel のプロジェクト `sonae-test` を削除 → GitHub の `test`
  ブランチを削除 → Neon の `test` ブランチを削除。他の環境には影響しない。
- **固定のテストアカウント**: `dev@sonae.local`（表示名「テストアカウント（消さないでください）」）を、
  動作確認のたびに使う固定アカウントとして置いてある。カテゴリ「旅行・出張」の下に、
  済んだ予定（「【テスト】出張の例」）と進行中の予定（「【テスト】出張の例2」）を 1 件ずつ用意済み。
  - **ログイン方法**: 本番ビルド（`NODE_ENV=production`）では `/api/auth/dev-login` は無効
    （`lib/dev-login.ts`）。そのため、ローカルで `next dev` を起動し、`DATABASE_URL` / `DIRECT_URL`
    だけテスト用 Neon ブランチに差し替えて（`APP_BASE_URL=http://localhost:3010`、
    `ENABLE_DEV_LOGIN=true`）、ローカルの `/api/auth/dev-login` を開くとこのアカウントでログインする
    （無ければ自動作成）。sonae-test.vercel.app 自体にはこの方法ではログインできない
    （Google ログインのみ）。
  - 確認が終わっても、このアカウントとデータは**消さない**（次回また使うため）。内容を大きく
    変えるテストをしたら、済んだ予定・進行中の予定それぞれ 1 件という最小構成に戻しておく。
- **テストデータの作成・削除スクリプト**: `scripts/test-user-isolation.mjs` は、テストユーザーを 2 人
  作って「互いのデータが見えないこと」を検証し、最後に必ず削除する。実行には
  `CONFIRM_TEST_DB=1` の指定が必要（テスト用 DB に対してのみ実行すること）。
