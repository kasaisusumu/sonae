# 私のマニュアル「そなえ」さん — 本番とテスト環境の差分（エンジニア向け）

「今この時点で」本番（`sonae` / `main`）とテスト環境（`sonae-test` / `test`）に
どんな違いがあるかだけを記録するドキュメントです。恒久的な仕様・作り方は
`機能仕様_テスト環境_エンジニア向け.md` と `テスト環境構築手順.md` を参照してください。

> **メンテナンス方針**: コード・環境変数・インフラ設定のいずれかで本番とテストに
> 差が生まれたとき、あるいは差が解消されたときは、**その変更と同じコミットで**
> このファイルを更新すること。「恒久的にこうなっている」ことではなく「今どう違うか」
> だけを書く（恒久的な仕組みは `機能仕様_テスト環境_エンジニア向け.md` 側に書く）。

---

## 現在の状態（2026-09-30 時点）

### コード

`main`（本番）と `test`（テスト環境）で、**アプリケーションコードの差分は無し**。
`test` にはテスト環境のインフラ整備専用のコミットが2つ余分にあるが、
アプリの挙動には無関係（本番に持ち込む必要もない）:
- Vercel の git 連携で初回ビルドを起動するための空コミット
- `vercel link` が `.gitignore` に追加したエントリを反映したコミット

→ `test` で作業中の未マージの機能変更がある場合は、ここに
「`test` にあって `main` にまだ無い変更」を具体的に追記すること
（コミットハッシュ・変更内容・マージ予定の有無）。

### インフラ

| 項目 | 本番 | テスト環境 |
| --- | --- | --- |
| Vercel プロジェクト | `sonae` | `sonae-test` |
| URL | `https://sonae-teal.vercel.app` | `https://sonae-test.vercel.app` |
| 追跡ブランチ | `main` | `test` |
| DB | Neon `sonae` プロジェクトの本体ブランチ | 同プロジェクトのブランチ `test` |
| 検索エンジンへの公開 | 公開（`NOINDEX` 未設定） | 非公開（`NOINDEX=true`） |
| Deployment Protection | （本番の設定に準ずる） | 無効化済み |
| Google Calendar webhook（即時同期） | 設定済み | 未設定 |
| GitHub Actions 定期ポーリング対象 | 対象（`APP_BASE_URL` Secrets） | 対象外 |

### 環境変数

| 変数 | 差分の有無 |
| --- | --- |
| `DATABASE_URL` / `DIRECT_URL` | **差分あり**（別の Neon ブランチ） |
| `APP_BASE_URL` | **差分あり**（別ドメイン） |
| `GOOGLE_REDIRECT_URI` | **差分あり**（別ドメイン） |
| `NOINDEX` | **差分あり**（本番は未設定、テストは `true`） |
| 上記以外すべて（Google OAuth クライアント鍵、OpenAI キー、VAPID 鍵、
  `SESSION_SECRET`、`ADMIN_EMAIL`、`CRON_SECRET` など） | 差分なし（共用） |

## 更新の仕方

- `test` にコードを追加してまだ `main` にマージしていない間は、「コード」節に
  何が未反映かを具体的に追記する。マージしたら該当箇所を消す（差分無しに戻す）。
- 環境変数・インフラ設定を追加・変更したら、上の表をその場で直す。
- 本番昇格の手順自体は `テスト環境構築手順.md`「コードの更新の仕方」を参照。
