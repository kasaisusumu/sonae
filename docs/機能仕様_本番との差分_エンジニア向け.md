# 私のマニュアル「そなえ」さん — 本番とテスト環境の差分（エンジニア向け）

「今この時点で」本番（`sonae` / `main`）とテスト環境（`sonae-test` / `test`）に
どんな違いがあるかだけを記録するドキュメントです。恒久的な仕様・作り方は
`機能仕様_テスト環境_エンジニア向け.md` と `テスト環境構築手順.md` を参照してください。

> **メンテナンス方針**: コード・環境変数・インフラ設定のいずれかで本番とテストに
> 差が生まれたとき、あるいは差が解消されたときは、**その変更と同じコミットで**
> このファイルを更新すること。「恒久的にこうなっている」ことではなく「今どう違うか」
> だけを書く（恒久的な仕組みは `機能仕様_テスト環境_エンジニア向け.md` 側に書く）。

## 現在の状態（2026-09-30 時点）

### コード

**`test` に、`main`（本番）にはまだ無い大きな機能変更がある**（未マージ）:

- **「未来の自分へのメッセージ」機能を新規追加**し、**失敗ログ機能（再発防止の警告・
  節約ダッシュボード・「防ぎたい失敗」オンボーディング）を全廃**した。
  新規テーブル `FutureMessage` / `EventFutureMessage` / `MessageProposalRecord`、
  `Event` に列2つ追加（`futureMessageCheckedAt` / `messageReviewNotifiedAt`）。
  旧 `FailureLog` / `SavingsEntry` / `FailureDismissal` テーブルと `Event` の関連列は
  **削除せず未使用のまま残置**（コード・UI からの参照は全部外した）。
  詳細な内部仕様は `機能仕様_エンジニア向け.md` §6、ユーザー向けの見え方は
  `機能仕様_ユーザー向け.md` §4.5/4.6/§5 を参照。
- **本番昇格時の注意**:
  1. マイグレーション `prisma/migrations/20260930150000_future_messages/` を
     **本番 DB にも `prisma migrate deploy` で当てる**（新規テーブル・新規列の追加のみ。
     破壊的変更は無い）。
  2. `sectionOrder` の旧センチネル `"@faillog"` は `lib/sections.ts` の
     `parseSectionOrder` が読み込み時に自動で除去するので、既存データの移行作業は不要。
  3. `public/sw.js` のバージョンを v12→v13 に上げてある（プッシュ通知タグを
     `failcheck-`→`futuremsg-`/`msgreview-` に変更したため）。
  4. `scripts/test-user-isolation.mjs`（ユーザー分離監査）をテスト DB に対して実行し、
     合格を確認してからマージすることを推奨。
- マージが完了したら、この節を「差分なし」に戻すこと。

`test` にはこれとは別に、テスト環境のインフラ整備専用のコミットも数件あるが、
アプリの挙動には無関係（本番に持ち込む必要もない）:
- Vercel の git 連携で初回ビルドを起動するための空コミット
- `vercel link` が `.gitignore` に追加したエントリを反映したコミット

## 更新の仕方

- `test` にコードを追加してまだ `main` にマージしていない間は、「コード」節に
  何が未反映かを具体的に追記する。マージしたら該当箇所を消す（差分無しに戻す）。
- 環境変数・インフラ設定を追加・変更したら、上の表をその場で直す。
- 本番昇格の手順自体は `テスト環境構築手順.md`「コードの更新の仕方」を参照。
