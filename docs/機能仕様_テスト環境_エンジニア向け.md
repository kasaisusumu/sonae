# 私のマニュアル「そなえ」さん — テスト環境 機能仕様（エンジニア向け）

本番に影響しないテスト環境（`sonae-test`）が「今どういう構成で、どう動くか」をまとめた
リファレンスです。作り方の手順は `テスト環境構築手順.md`、本番との今の差分は
`機能仕様_本番との差分_エンジニア向け.md`、アプリ本体の仕様は `機能仕様_エンジニア向け.md`
を参照してください。

> **メンテナンス方針**: テスト環境のインフラ構成・環境変数・挙動を変えたら、
> このファイルも同じコミットで更新すること。

---

## 1. これは何か

本番（`sonae`プロジェクト）とアプリケーションコードは共通のまま、**別の Vercel プロジェクト・
別のデータベースブランチ**で動かしている、動作確認専用の環境。目的は「本番の URL・本番の
データに一切触れずに、実機に近い形で動作確認する」こと。

## 2. インフラ構成

| 項目 | 内容 |
| --- | --- |
| Vercel プロジェクト | `sonae-test`（本番は `sonae`。別プロジェクト） |
| URL | `https://sonae-test.vercel.app` |
| 追跡する git ブランチ | `test`（git 連携済み。push すると自動デプロイ） |
| DB | Neon プロジェクト `sonae`（本番と同じプロジェクト）内の**ブランチ `test`**
  （id `br-bold-credit-a7vvz8fg`）。書き込みは本番ブランチと完全に分離 |
| Deployment Protection（SSO） | 無効化済み（有効だとログインしていない人が使えないため） |
| Framework Preset | `nextjs`（`vercel project add` で作った直後は自動判定されず
  `Other` になるので、REST API で手動修正した経緯あり） |

## 3. 環境変数

| 変数 | テスト環境での値 |
| --- | --- |
| `DATABASE_URL` / `DIRECT_URL` | テスト用 Neon ブランチの接続文字列（本番とは別） |
| `APP_BASE_URL` | `https://sonae-test.vercel.app` |
| `GOOGLE_REDIRECT_URI` | `https://sonae-test.vercel.app/api/auth/google/callback` |
| `NOINDEX` | `true`（§4 参照） |
| それ以外（Google OAuth クライアントの鍵、OpenAI キー、VAPID 鍵、`SESSION_SECRET`、
  `ADMIN_EMAIL`、`CRON_SECRET` など） | **本番と共用**。同じ値を設定している |

共用している変数がある以上、Google Calendar API・OpenAI API の利用枠（quota）・課金は
本番とテスト環境で共有される点に注意（§5）。

---

## 4. 検索エンジンに出さない仕組み（NOINDEX）

- `app/robots.ts` が `process.env.NOINDEX === "true"` のとき `/robots.txt` を
  `Disallow: /` にする。
- `app/layout.tsx` の `metadata.robots` も同条件で `{ index: false, follow: false }` を
  出し、`<meta name="robots" content="noindex, nofollow">` を付与する（二重の対策）。
- 本番にはこの変数を設定していないので、本番は従来どおり検索エンジンに出る。

---

## 5. 既知の制約

- **自動通知（新規予定のプッシュ通知）が届かない**: GitHub Actions の定期ポーリング
  （`poll-calendar`）は本番の `APP_BASE_URL`（Secrets）だけを叩く設定。テスト環境の
  新着予定は、アプリを開いたとき・手動の「カレンダーから取り込む」でのみ反映される。
- **Google Calendar の即時 webhook 同期は未設定**（ドメインごとの確認が必要なため）。
- **マイグレーションは自動反映されない**: `prisma/migrations` に追加したら、本番だけで
  なくテスト用 Neon ブランチにも手動で `prisma migrate deploy` を当てる必要がある
  （`テスト環境構築手順.md`「マイグレーションの当て方」参照）。
- **API 利用枠・課金が本番と共用**: Google Calendar API・OpenAI API のキーが同じため、
  テスト環境での大量アクセスは本番の利用枠にも影響し得る。
