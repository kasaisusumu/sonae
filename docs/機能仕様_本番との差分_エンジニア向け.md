## 追補: 下部バーのキーボード検知を修正 — 未反映（2026-10-24〜、1023系とは無関係）

`app/components/bottom-nav.tsx`の`useKeyboardOpen`が、`visualViewport`の縮み幅
（しきい値150px）と入力欄へのフォーカスの**両方**が true のときだけ下部バーを
隠す方式だったが、iOSのPWAスタンドアロン（ホーム画面に追加して開いた状態）では
キーボード表示時に`visualViewport`の`resize`イベントが遅れて発火する・環境により
ほぼ発火しないことがあり、縮み幅の確認を待っている間（あるいはいつまでも）隠れず、
下部バーがキーボードの上に“せり上がって”見える不具合があった（ユーザー指摘
「キーボード出した時にメニューバーがその上に上がってくる」）。
`visualViewport`には一切依存せず、**入力欄のフォーカス有無だけ**で判定するよう
変更した（このバー自体`sm:hidden`でスマホ幅でしか出ないため、フォーカス＝
ほぼ確実にキーボードが出る、という前提）。

**追記（2026-10-24のバグレビューで発覚・修正）**: 上記の単純化が、チェック
ボックス等キーボードを呼ばないinput要素にフォーカスしただけでも下部バーを
隠してしまう退行を生んでいた（急ぎ/そのうちの完了・復活チェックボックス自体が
引き金）。`isEditableElement`に`input.type`の判定を追加し、`checkbox`/
