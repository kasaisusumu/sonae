# そなえ デプロイ手順（Vercel + Neon・完全無料 / カード不要）

所要 40〜60分。上から順に。**◆ コピペ** はそのまま貼る値。
秘密の値（`GOOGLE_CLIENT_SECRET` / `OPENAI_API_KEY` / `VAPID_PRIVATE_KEY` / `CRON_SECRET`）は
このファイルには書いていないので、**エディタで `.env` を開いてコピー**してください。

構成:
- **Vercel**（無料 Hobby）… Next.js アプリ本体
- **Neon**（無料 Postgres）… データベース
- **GitHub Actions**（無料）… 5分おきに新規予定をチェックして通知（`.github/workflows/poll.yml` 同梱済み）

---

## 手順1: GitHub（済み）

コードは既に https://github.com/kasaisusumu/sonae （`main`）に push 済み。
以後コードを直したら `git add -A && git commit -m "..." && git push` で更新 → Vercel が自動再デプロイ。

---

## 手順2: Neon（無料 Postgres を作る）

1. https://neon.tech を開き **「Sign up」→ GitHub でサインイン**（カード不要）
2. 「Create project」→ 名前 `sonae`、リージョンは近い所（例: Asia Pacific (Tokyo)）→ Create
3. 作成後の **「Connection string」** パネルで、次の2つをコピーする:
   - **Pooled connection**（`-pooler` が入っている方）→ これが `DATABASE_URL`
   - **Direct connection**（`-pooler` が入っていない方）→ これが `DIRECT_URL`
   - どちらも末尾に `?sslmode=require` が付いていること（Pooled は `&pgbouncer=true` も付ける）
   ※ パネルの「Pooled connection」チェックボックスを切り替えると両方の形が見られます。
4. この2つの文字列を手元に控える（手順4で Vercel に貼る）

---

## 手順3: Google Cloud Console

https://console.cloud.google.com を開き、**OAuth クライアントを作ったプロジェクト**を選択。

### 3-1. Calendar API を有効化
左メニュー **「API とサービス」→「有効な API とサービス」→「＋ API とサービスの有効化」**
→ `Google Calendar API` を検索 → **有効にする**（既に有効なら不要）

### 3-2. OAuth 同意画面を「テスト」に & テストユーザー追加
左メニュー **「API とサービス」→「OAuth 同意画面」**
- 公開ステータスが **「テスト」** であること（「本番環境に push」は押さない＝押すと審査が必要）
- 下の **「テストユーザー」→「＋ ADD USERS」** に、**使う人全員の Gmail アドレス**（自分も）を追加 → 保存
  （ここに無いアカウントはログイン不可。最大100人）

### 3-3. リダイレクト URI（手順4で URL 確定後に戻ってくる）
左メニュー **「API とサービス」→「認証情報」** → 対象の **OAuth 2.0 クライアント ID** をクリック
→ **「承認済みのリダイレクト URI」→「＋ URI を追加」** に次を追加（`sonae` は実際の Vercel URL に合わせる）:
```
https://sonae.vercel.app/api/auth/google/callback
```
ローカル用も残す:
```
http://localhost:3000/api/auth/google/callback
```
→ **保存**（反映に数分かかることあり）

## 手順4: Vercel

### 4-1. プロジェクト作成
1. https://vercel.com を開き **GitHub でサインアップ**（カード不要）
2. **「Add New...」→「Project」** → `kasaisusumu/sonae` を **Import**
3. Framework Preset は **Next.js**（自動判定）。**Build/Output 設定はそのまま**（`package.json` の `build` が
   `prisma generate && prisma migrate deploy && next build` になっており、デプロイ時に DB テーブルを自動作成する）
4. **「Environment Variables」** を開き、下表を全部追加（Environment は Production / Preview / Development すべてにチェック）

| Key | Value |
| --- | --- |
| `DATABASE_URL` | 手順2の **Pooled** 接続文字列 |
| `DIRECT_URL` | 手順2の **Direct** 接続文字列 |
| `SESSION_SECRET` | 長いランダム文字列（`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` の出力） |
| `APP_BASE_URL` | `https://sonae.vercel.app`（※ 4-3 で実 URL に直す） |
| `GOOGLE_REDIRECT_URI` | `https://sonae.vercel.app/api/auth/google/callback` |
| `GOOGLE_CLIENT_ID` | `.env` の値 |
| `GOOGLE_CLIENT_SECRET` | `.env` の値 |
| `OPENAI_API_KEY` | `.env` の値 |
| `OPENAI_MODEL` | `gpt-4o-mini` |
| `VAPID_PUBLIC_KEY` | ◆ コピペ（下） |
| `VAPID_PRIVATE_KEY` | `.env` の値 |
| `VAPID_SUBJECT` | `mailto:kadomimo0504@gmail.com` |
| `CRON_SECRET` | `.env` の値 |

◆ コピペ（VAPID_PUBLIC_KEY — 公開鍵なので共有可）
```
BKkxcsMMOHHgJbcwHFlK9mRXmVishzJ9PJ9jjKpyii0NHpMqhMt0xuyBrSld8D7wDU40-6Ic-BWog3TWUNjqlEo
```

5. **「Deploy」** をクリック → ビルド 3〜6分。ログに `Applying migration` → `✓ Compiled` が出れば成功。

### 4-2. うまくいかない時（ビルドで migrate 失敗）
`prisma migrate deploy` が `DIRECT_URL` に繋げないとビルドが落ちる。
→ Neon の Direct 接続文字列（`-pooler` 無し・`?sslmode=require` 付き）を `DIRECT_URL` に入れ直して再デプロイ。

### 4-3. 実 URL の確認と修正
1. デプロイ完了後、Vercel のプロジェクト画面上部の **Production ドメイン**を確認（例 `https://sonae.vercel.app`）
2. `https://sonae.vercel.app` 以外だったら、**Settings → Environment Variables** で
   `APP_BASE_URL` と `GOOGLE_REDIRECT_URI` を実 URL に修正 → **Redeploy**
3. **手順3-3 に戻り**、Google 側のリダイレクト URI も実 URL にする

## 手順5: GitHub Actions（5分おきの通知チェックを有効化）

1. https://github.com/kasaisusumu/sonae を開く → **Settings → Secrets and variables → Actions**
2. **「New repository secret」** で2つ登録:
   | Name | Secret |
   | --- | --- |
   | `APP_BASE_URL` | Vercel の実 URL（例 `https://sonae.vercel.app`） |
   | `CRON_SECRET` | `.env` の値（Vercel に入れたものと同じ） |
3. **Actions** タブ → 左の **「poll-calendar」** → ワークフローが無効なら「Enable workflow」
4. 「Run workflow」で手動実行してみて、緑になれば OK（以後は自動で約5分おき）
   ※ GitHub の定期実行は混雑時に数分〜十数分遅れることがある。厳密な即時性が要るなら
   後述の cron-job.org を使う。

### （任意）もっと確実にしたい場合: cron-job.org
1. https://cron-job.org に無料登録（カード不要）
2. 「Create cronjob」→ URL に `https://sonae.vercel.app/api/cron/poll`、方式 **POST**
3. 「Advanced」→ Headers に `x-cron-secret: <CRON_SECRET の値>`
4. 実行間隔 5分 → 保存。（GitHub Actions 側は止めてOK）

## 手順6: スマホで使う・通知をオンにする

### Android（Chrome）
1. `https://sonae.vercel.app` を開く → 「Google でログイン」→ **テストユーザーのアカウント**
2. メニュー(︙) → 「アプリをインストール」/「ホーム画面に追加」
3. アプリ内 **設定 → 通知 → 「通知をオンにする」** → 許可 → 「テスト通知を送る」で確認

### iPhone（Safari, iOS 16.4+）
1. Safari で `https://sonae.vercel.app` → 共有 → **「ホーム画面に追加」**
2. **ホーム画面のアイコンから開く**（Safari のままだと通知不可）
3. 「Google でログイン」→ テストユーザー → **設定 → 通知 → 「通知をオンにする」** → 許可 → テスト通知

### 動作確認
スマホの Google カレンダーに数日先の予定を1件追加 → 5〜15分待つ → 「新しい予定が追加されました」が届けば成功。

## うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| ビルドが `P1001` / `can't reach database` で落ちる | `DIRECT_URL`（`-pooler` 無し）が正しいか。Neon プロジェクトが起動中か |
| 実行時に接続エラー | `DATABASE_URL` は **Pooled**（`-pooler` & `pgbouncer=true`）にする |
| ログインで `redirect_uri_mismatch` | Google の「承認済みリダイレクト URI」と `GOOGLE_REDIRECT_URI` が完全一致（末尾スラッシュ・https も） |
| ログインで「アクセスをブロック」 | そのアカウントが Google の「テストユーザー」に入っているか |
| テスト通知は届くが予定通知が来ない | GitHub Actions「poll-calendar」のログを見る。`APP_BASE_URL` / `CRON_SECRET` の secret 設定漏れが多い |
| iPhone で「通知をオンにする」が押せない/出ない | ホーム画面に追加したアイコンから開いているか。iOS 16.4 以上か |
| 7日ごとにログアウトされる | Google テストモードの仕様（リフレッシュトークン7日失効）。再ログインで復帰 |
