# My Jam(working title) — Web App 開発仕様書 (MVP)

## 1. プロダクト概要

予定をカレンダーに入れるだけで、その予定に必要な準備リストを自動生成し、ユーザーの編集内容を学習して「自分専用マニュアル」に育てていくアプリ。過去の失敗(うっかり損失)を記録すると、類似の予定で自動的に警告を出し、再発を防ぐ。防いだ失敗の推定損失額を月次で可視化する。

ターゲット: 注意の切り替えや段取りが苦手な人(ADHD傾向)。

## 2. このMVPの目的(検証したい問い)

これはプロダクション用アプリではなく、**3〜5名のユーザーに1週間使ってもらって検証するためのプロトタイプ**。以下を確認したい。

1. 「失敗ログをつける」という行為を、ユーザーが継続できるか
2. 節約額ダッシュボードが、課金意思(WTP)を動かす実感につながるか
3. 「編集を学習して次回反映」という体験が、実際に「自分に合ってきた」と感じられるか

この目的から外れる作り込み(本番品質の認証基盤、実カレンダー連携、決済など)は今回は不要。**動くものを最速で3〜5人に触ってもらう**ことを優先する。

## 3. コア機能(優先順位順)

### 3.1 予定の登録(P0)
- **Google Calendar 連携が必須要件。** OAuth 2.0でユーザーのGoogleアカウントに接続し、Google Calendar APIで予定を取得する
  - 直近〜将来の予定を一覧取得し、そなえ側のEventとして取り込む
  - 新規予定の検知(polling、またはpush通知/Webhookが簡単に組めるならそちらでも可。MVPでは数分おきのpollingで十分)
  - 取り込んだ予定にカテゴリを付与する必要がある(Googleカレンダー側にはカテゴリ概念がないため、そなえ側で予定タイトル・説明文からカテゴリを推定し、ユーザーが確認・修正できるようにする)
- 手動でのカテゴリ修正・予定の直接登録(カレンダーに入れる前に試したい場合)も画面上でできるようにする
- カテゴリ例: 旅行・出張、通院、来客対応、契約・手続き、その他(ユーザーが自由入力できるようにする)

### 3.2 準備リストの自動生成(P0)
- 予定のカテゴリ・タイトル・日時から、準備タスクを生成する
- MVPでは、Claude APIに予定情報を渡し、準備タスク(タイトル・タイミング・チェックボックス)をJSONで返してもらう形でよい(ルールベースにこだわらない)
- 生成後、ユーザーがそのリストを編集(追加・削除・タイミング変更)できる

### 3.3 編集の学習("自分マニュアル")(P0)
- ユーザーがリストを編集した内容を、カテゴリ単位で記憶する
- 次回、同じカテゴリの予定を登録したときに、過去の編集を反映した状態でリストを生成する(例: 「ホテルは不要」と一度消したら、次回から旅行カテゴリでは出さない)
- 実装方針: カテゴリごとに「学習済みの除外項目・固定項目・タイミング調整」を保存し、生成プロンプトに含める、あるいは生成後にルールで後処理する。凝った機械学習は不要。

### 3.4 失敗ログ & 再発防止(P1)
- 「うっかり失敗」を記録する簡単なフォーム(何が起きたか、推定損失額、関連カテゴリ)
- 同カテゴリの予定を新規登録した際、過去の失敗ログがあれば警告として表示する
  - 例: 「前回、このカテゴリで『新幹線に乗り遅れ、¥25,000の損失』がありました。今回は出発1時間前のリマインドを追加しますか?」

### 3.5 節約額ダッシュボード(P1)
- 失敗ログに基づき、「防げた」とユーザーが確認した項目の推定損失額を積み上げて表示
- 月次の合計、カテゴリ別内訳、月ごとの推移グラフ
- **「推定節約額」であることを明示**し、断定的な表現(「あなたは¥18,400節約しました」等の言い切り)は避ける。「参考値」「推定ロジック: ○○」という注記を必ず添える
- ユーザーが「これは防げた」と自己申告するシンプルな仕組みでよい(自動判定は不要)

### 3.6 簡易フィードバック導線(P1)
- 各画面の隅に「このアプリに月いくらなら払いたいか」等、軽いフィードバックを収集できる導線(1問アンケート程度)を仕込む。WTP検証のため。

## 4. データモデル(参考)

```
User
  - id, name, email

Category
  - id, user_id, name (例: 旅行・出張, 通院, 来客対応)

Event
  - id, user_id, category_id, title, event_datetime, memo, created_at
  - google_event_id (nullable, unique)  // Google Calendar側のイベントID。手動登録の場合はnull
  - source ("google" | "manual")

UserGoogleAccount  // Google連携用のトークン管理
  - id, user_id, google_account_email, access_token, refresh_token, token_expiry, calendar_id, last_synced_at

ChecklistItem
  - id, event_id, title, timing_label (例: "前日21時"), is_done, is_user_added, is_user_removed

CategoryLearning  // 「自分マニュアル」の実体
  - id, category_id, excluded_items (json配列), fixed_items (json配列), timing_overrides (json)

FailureLog
  - id, user_id, category_id, description, estimated_loss_yen, occurred_at

SavingsEntry
  - id, user_id, event_id, failure_log_id (nullable), amount_yen, confirmed_by_user (bool), created_at
```

## 5. 画面一覧

1. **ダッシュボード(ホーム)** — 今月の推定節約額、直近の予定、失敗ログの警告があれば表示
2. **Google連携設定** — 「Googleカレンダーと接続」ボタン→OAuth認証→どのカレンダーを同期するか選択
3. **予定一覧・新規登録** — Googleから取り込んだ予定の一覧(カテゴリ推定結果を確認・修正)+ 手動登録フォーム→カテゴリ選択→準備リスト自動生成
4. **予定詳細・チェックリスト編集** — チェックリストの編集(この編集がCategoryLearningに反映される)
5. **失敗ログ一覧・新規登録**
6. **節約額ダッシュボード** — 月次推移グラフ、カテゴリ別内訳
7. **簡易設定/フィードバック** — WTPアンケート、Google連携の管理(再接続・解除)

## 6. 推奨技術スタック

- **フレームワーク**: Next.js (App Router) + TypeScript
- **スタイリング**: Tailwind CSS
- **DB**: SQLite(ローカル検証用)+ Prisma ORM。将来的にPostgres(Supabase等)へ移行しやすい構成にする
- **AI生成**: Anthropic API(Claude)を準備リスト生成に使用。APIキーは環境変数で管理し、リポジトリにコミットしない
- **Google Calendar連携**: Google Calendar API + OAuth 2.0(`googleapis` npmパッケージを利用)。Google Cloud ConsoleでOAuthクライアントID発行が事前に必要(このステップはユーザー側で行う)。スコープは `calendar.readonly` で足りる(そなえ側から書き込みはしない前提)
- **認証**: MVPではGoogleログイン自体をユーザー認証として使い、そなえ独自のID/パスワード管理は不要にする(実装がシンプルになる)。複数人でのプロトタイプテストでも、各自のGoogleアカウントでログインしてもらえばよい
- **デプロイ**: Vercel(検証用に手早く公開できる)

## 7. スコープ外(MVPでは作らない)

- Google以外のカレンダー連携(Outlook等)
- カレンダーへの書き込み(準備タスクをGoogle Calendar側に予定として追加する機能。読み取りのみでよい)
- 決済・課金機能(WTPは画面上のアンケートで代替検証)
- プッシュ通知・メール通知(画面内表示で十分)
- 本格的な認証・権限管理
- モバイルアプリ化

## 8. デザインの方向性

- テーマカラー: ティール系(`#028090` を基調、アクセントに `#02C39A`)
- トーン: 落ち着いた、責める感じのない、やさしいUI(ターゲットが「うっかり」を責められると離脱しやすいため)
- 節約額の数字は大きく・ポジティブに見せる一方、推定値である旨は小さくても必ず表示する
