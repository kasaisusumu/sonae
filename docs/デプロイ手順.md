## 手順1: GitHub にコードを上げる

### 1-1. リポジトリを作る
1. ブラウザで https://github.com/new を開く
2. **Repository name**: `sonae`（好きな名前でOK）
3. **Private** を選択
4. 「Add a README」「Add .gitignore」「license」は**すべてチェックしない**
5. **Create repository** をクリック
6. 次の画面に出る URL を控える。例: `https://github.com/あなたのID/sonae.git`

### 1-2. push する（ターミナルで実行）
プロジェクトフォルダ（`260830`）で、以下を1行ずつ実行します。
`<あなたのリポジトリURL>` は 1-1 で控えた URL に置き換えてください。

```bash
git add .
git commit -m "そなえ MVP: P0/P1 + PWA + Web Push + Render 構成"
git branch -M main
git remote add origin <あなたのリポジトリURL>
git push -u origin main
```

> ※ この 1-2 のコミット作成は、こちら（Claude）で代行できます。頼む場合は「コミットして」と言ってください。
> GitHub への push はあなたの GitHub 認証が必要なので、push はあなたが実行します。

## 手順2: Google Cloud Console の設定

ブラウザで https://console.cloud.google.com を開き、**このアプリの OAuth クライアントを作ったプロジェクト**を選択（画面上部のプロジェクト名をクリックで切替）。

### 2-1. Calendar API を有効化
1. 左メニュー → **「API とサービス」→「有効な API とサービス」**
2. 上部 **「＋ API とサービスの有効化」**
3. 検索で `Google Calendar API` → クリック → **「有効にする」**
（すでに有効なら「管理」と出ます。そのままでOK）

### 2-2. OAuth 同意画面をテストモードに
1. 左メニュー → **「API とサービス」→「OAuth 同意画面」**
2. **User Type** が「外部」、公開ステータスが **「テスト」** になっていることを確認
   （「本番環境に push」は押さないでください。押すと審査が必要になります）
3. 下の方の **「テストユーザー」→「＋ ADD USERS」**
4. **このアプリを使う人全員の Gmail アドレス**を1行ずつ入力（あなた自身も必ず追加）→ 保存
   - ここに入っていないアカウントはログインできません（最大100人）

### 2-3. リダイレクト URI を追加
1. 左メニュー → **「API とサービス」→「認証情報」**
2. **「OAuth 2.0 クライアント ID」**の一覧から、このアプリ用のものをクリック
3. **「承認済みのリダイレクト URI」→「＋ URI を追加」**
4. ◆ コピペ（`sonae` の部分は手順3で確定した実際の URL に合わせる）
   ```
   https://sonae.onrender.com/api/auth/google/callback
   ```
5. ローカル開発用に、これも残す or 追加:
   ```
   http://localhost:3000/api/auth/google/callback
   ```
6. **保存**

> ※ 手順3で Render の URL が `https://sonae.onrender.com` 以外になった場合は、
> ここに戻って正しい URL に直してください（保存後、反映まで数分かかることがあります）。

## 手順3: Render でデプロイ

### 3-1. Blueprint を作成
1. ブラウザで https://dashboard.render.com を開く（アカウントが無ければ GitHub でサインアップ）
2. 右上 **「New +」→「Blueprint」**
3. 「Connect a repository」で、手順1で作った `sonae` リポジトリを選ぶ
   （初回は Render に GitHub 連携の許可を求められます → Authorize）
4. Render が `render.yaml` を読み、**`sonae`（Web）** と **`sonae-poll`（Cron）** の2つが表示される
5. **「Apply」** をクリックする前に、下に出る環境変数の入力欄を埋めます（次の 3-2）

### 3-2. 環境変数を入力

**`sonae`（Web サービス）** の欄:

| キー | 値 |
| --- | --- |
| `APP_BASE_URL` | `https://sonae.onrender.com` （※下の注参照） |
| `GOOGLE_REDIRECT_URI` | `https://sonae.onrender.com/api/auth/google/callback` |
| `GOOGLE_CLIENT_ID` | `.env` の値をコピペ |
| `GOOGLE_CLIENT_SECRET` | `.env` の値をコピペ |
| `OPENAI_API_KEY` | `.env` の値をコピペ |
| `VAPID_PUBLIC_KEY` | このファイル上部の ◆ コピペ |
| `VAPID_PRIVATE_KEY` | `.env` の値をコピペ |
| `VAPID_SUBJECT` | `mailto:kadomimo0504@gmail.com` |
| `CRON_SECRET` | `.env` の値をコピペ |

**`sonae-poll`（Cron）** の欄:

| キー | 値 |
| --- | --- |
| `APP_BASE_URL` | Web と同じ値 |
| `CRON_SECRET` | Web と同じ値 |

> **注（URL の確定について）**: Render はサービス名 `sonae` が空いていれば `https://sonae.onrender.com` を、
> 埋まっていれば `https://sonae-xxxx.onrender.com` を割り当てます。
> まず上記のとおり `sonae` 前提で入力して **Apply**。デプロイ後に実 URL を確認し（3-4）、
> 違っていたら `APP_BASE_URL` と `GOOGLE_REDIRECT_URI`（Render と Google の両方）を実 URL に直します。

### 3-3. デプロイ実行
1. **「Apply」** をクリック
2. ビルドが始まる（Docker ビルド。初回は 5〜10 分）
3. `sonae` サービスのログに `[entrypoint] next start on :3000` が出れば起動成功

### 3-4. 実 URL の確認と修正
1. Render ダッシュボード → `sonae` サービスのページ上部にある URL を確認
   （例: `https://sonae.onrender.com`）
2. その URL が上で入力した値と違う場合:
   - `sonae` → **Environment** タブ → `APP_BASE_URL` と `GOOGLE_REDIRECT_URI` を実 URL に修正 → **Save Changes**
   - `sonae-poll` → **Environment** → `APP_BASE_URL` を修正 → Save
   - **手順2-3 に戻り**、Google 側のリダイレクト URI も実 URL に修正
3. 保存すると自動で再デプロイされます

## 手順4: スマホで使う・通知をオンにする

### Android（Chrome）
1. Chrome で `https://sonae.onrender.com` を開く
2. 「Google でログイン」→ **テストユーザーに登録したアカウント**を選択
3. メニュー（︙）→「アプリをインストール」または「ホーム画面に追加」
4. アプリ内で **設定 → 通知 → 「通知をオンにする」** → 許可 → 「テスト通知を送る」で確認

### iPhone（Safari）※ iOS 16.4 以上
1. Safari で `https://sonae.onrender.com` を開く
2. 共有ボタン → **「ホーム画面に追加」**
3. **ホーム画面にできたアイコンから開く**（Safari のままだと通知を使えません）
4. 「Google でログイン」→ テストユーザーのアカウント
5. **設定 → 通知 → 「通知をオンにする」** → 許可 → 「テスト通知を送る」

### 動作確認
1. スマホの Google カレンダーで、数日先に予定を1件追加する
2. 最大5分待つ（Cron が5分間隔のため）
3. 「新しい予定が追加されました」という通知が届く → 成功

## うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| ログインで `redirect_uri_mismatch` | Google 側の「承認済みリダイレクト URI」と `GOOGLE_REDIRECT_URI` が完全一致しているか（末尾スラッシュ・http/https も） |
| ログインで「アクセスをブロック」 | そのアカウントが Google の「テストユーザー」に入っているか |
| 通知が来ない | 設定画面で「テスト通知を送る」が届くか → 届かないなら端末の通知許可。届くのに予定通知が来ないなら Render の `sonae-poll` ログを見る（`APP_BASE_URL` / `CRON_SECRET` 不一致が多い） |
| 最初のアクセスが遅い | Render starter はアイドルでスリープ。数十秒待つ |
| 「予定が7日で急にログアウト」 | Google テストモードの仕様（リフレッシュトークン7日失効）。再ログインで復帰 |
